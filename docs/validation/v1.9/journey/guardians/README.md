# Guardian encounter engine proof

`GuardianCatalog` and `GuardianEncounter` are an isolated optional mode. They do not change `Board`, `Level`, the published L/M/T content, or existing challenge codes. One of 100 deterministic encounters becomes available per ten distinct Journey clears. Every encounter has at least one two-layer piece; the first four teach layer hits and ordinary exits, while encounter 5 introduces one-cell movement. At encounter 20 and beyond, every piece moves one cell per action after its extra layer has been removed.

The current and initial piece views are immutable. A hit on a two-layer piece removes exactly one layer in place. A one-cell piece then advances exactly one cell, or exits when its next cell is outside the board. Ordinary pieces exit only when the whole ray is clear. Pieces sharing a row point to the same border, creating front/back dependencies while preventing cycles. There are no timers or fabricated boss-health losses: `remainingWork` is the sum of remaining layer hits and remaining steps/exits.

This sum is both a lower bound and an achievable completion length. Every successful action decreases it by exactly one; each unsolved productive state has a legal action. All initial budgets therefore fit a real completion. A present blocked attempt consumes one action without changing work. Undo restores the last successful state and refunds that one productive action; it cannot erase failed probes. Free restart restores the original encounter and fixed budget. History can repeat a piece ID for a layer hit followed by multiple steps. The bounded canonical `G1` save validates the repeated actions, used counter and exact identity before accepting restoration.

Run `bash scripts/test-guardian-v19.sh`. The [coordinate/work oracle](../../../../../scripts/GuardianV19Test.java) independently derives legality and remaining work from snapshot coordinates; it does not reuse the engine's movement or cost function. It traverses every reachable productive state for all 100 encounter patterns, compares every legal transition, verifies exact Undo, samples complete plans and restoration, and separately tests charged blocked probes, exhaustion, missing taps, free restart, immutable snapshots and malformed records. The report records 100 unique patterns, **6,197,718 productive states**, **34,045,573 transitions** and **472,484,607 assertions**. These counts concern this engine version only; host run duration is not Android latency or human playtime.

The engine tests establish logical solvability and persistence contracts. Native touch feedback, visual thickness, the optional unlock flow, story text and receipt/collection UI require the separate Android and store tests in the release evidence.
